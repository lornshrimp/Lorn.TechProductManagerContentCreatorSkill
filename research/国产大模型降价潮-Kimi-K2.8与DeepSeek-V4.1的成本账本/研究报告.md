# 研究报告 · 国产大模型降价潮：Kimi K2.8 与 DeepSeek V4.1 的成本账本

## 一、研究简报

**研究对象**：2026 年 9 月 10—11 日，DeepSeek V4.1-Flash 与月之暗面 Kimi K2.8 Preview 的接连发布，及其对开发者与企业的真实成本影响。
**核心问题**："参数翻倍、推理反而更省"这句话，到底省在哪？哪些是真降本，哪些只是定价策略？
**研究深度**：L2（产品迭代 + 成本结构 + 选型判断）
**结论先行**：这一轮降价的底层是架构效率的兑现（KV 缓存压缩 + 非对称编解码 + 稀疏激活），不是补贴战；但"单价便宜"不等于"总价便宜"——token 消耗、缓存命中率、默认上下文长度三项，才是真正决定账单的变量。

## 三、写作素材库

**作者观点底座（notebook 直接可用）**
- 《AI大模型竞争与成本结构》："赌架构真降本"——降本若来自架构效率（缓存、稀疏、编解码），可持续且可复现；若来自补贴，则只是获客成本的前移。
- 同库："警惕国产登顶叙事"——音量与交付常成反比，性能数字要看三个月后还有没有人在用。
- 同库："开源收编"——开源既是生态扩张，也是把竞争对手的用户与反馈吸进自家迭代循环。

**六个成本账本（正文骨架）**
1. 缓存账：命中 $0.003 vs 未命中 $0.15，差 50 倍——Agent 场景的账单由命中率决定。
2. 参数账：552B 总参、输入仅激活 8B——"参数翻倍、激活减半"的稀疏化红利。
3. 架构账：20+20 层非对称编解码，预填充算力降近一半——长输入任务受益最大。
4. 价格账：跨厂商单价并排——$0.60 输出 vs $15（Kimi K3）/$20/$25。
5. 用量账：杰文斯悖论——单价降，token 消耗升；V4.1-Flash 单任务成本反而高于 V4-Flash。
6. 交付账：真降本 vs 假降本——四条判别标准。

**金句弹药（供润色阶段打磨）**
- 参数翻倍，激活减半——省的不是模型，是重复计算。
- 单价打下来的是账单的第一行，token 消耗决定的是最后一行。
- 缓存命中率，才是 Agent 时代的"电费"。
- 便宜的不是模型，是那部分没被重复算一遍的上下文。

**靶子（对立方观点）**
- "降价就是内卷，赔本赚吆喝" → 反驳：本轮降价伴随明确架构改动与基准数据，属效率兑现；但需承认补贴与效率在商业上常混在一起，判别要靠账本而非立场。
- "参数更小所以更弱" → 反驳：稀疏激活是容量与算力的解耦，判断强弱要看基准与场景，不看总参数。

## 四、竞品差异化

| 主流写法 | 本文差异化 |

| 只报单价 | 区分"单价便宜"与"总价便宜"（token 消耗、缓存命中率） |
| 唱多国产登顶 | 用"真降本/假降本"条件式表述，标注第三方口径与弱项（HLE 落后、鲁棒性待验证） |

## 五、研究结论

1. 本轮降价的底层是可解释的架构效率：KV 缓存压缩至约 1/4、非对称编解码把预填充算力砍近一半、稀疏激活让"总参数翻倍、激活反而减少"。
2. 开发者真正的成本变量有三个：缓存命中率、输出 token 量、默认上下文长度。只看单价会误判。
3. 可写、可立、可收藏的落点：一份"六个成本账本"的选型判断框架 + 一条"真降本 vs 假降本"的判别清单，避免陷入厂商叙事。
